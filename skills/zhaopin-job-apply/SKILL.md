# 智联岗位投递

把已获用户授权的岗位投递执行到可核对的结果。创建本技能、查看岗位或优化简历，本身不构成投递授权；用户已说“帮我投递/海投/继续投”且范围明确时直接执行，不逐条重复确认。授权范围内的“立即投递”可能同时发送网站默认招呼语；独立追问、谈薪及自拟额外消息需按用户授权处理。

## 确认范围与续办

- 先读当前工作目录中的求职资料、求职意向、历史投递记录和续办状态，核对登录账号的简历所属人。岗位、城市、薪资、平台及目标数量以用户最新要求为准；缺项优先沿用真实资料，不擅自降薪、改隐私、换平台或改简历。
- 用户要求“尽量多、产品相关都投”时，覆盖产品经理及软件/平台/AI/B端/C端等细分方向，也搜索需求分析、业务分析、BA、功能设计、交互/原型设计、产品助理、实施产品、解决方案产品等实际职责相近的岗位。不要将范围压缩成最容易成功的几个职位。
- 英语优先时，补充“英语 产品经理”“英文 需求分析”“Business Analyst”“海外 产品”等搜索。单独标记**明确语言要求**及**海外/跨国协作**，不要把职位中出现“全球”直接等同于要求英语。
- 搜索命中不代表适合投递：查看工作地点、实际职责及要求。区分软件需求分析与供应链需求预测、产品设计与纯销售、原型设计与机械打样；基于用户范围评估行业迁移与技能差距。不编造经历、资格或表单答案，不为凑数投错城市或明显无关的职位。
- 明确数量口径是本轮新增还是历史累计。既有口径沿用，未明确时说明采用的口径；不要偷偷将200降为20。跨日继续也不重置成功数量。时间安排遵循用户时区及最新延后/暂停要求；技能本身不会创建定时任务。

## 浏览器与实际投递

需要控制浏览器时读现有 `playwright` 技能。先检查 `npx` 与现有CLI会话，优先复用已登录浏览器，不复制用户浏览器档案或认证数据。Windows接入和本次界面观察见 [references/playwright-workflow.md](references/playwright-workflow.md)。

1. 在最新快照中确认搜索入口、地区和账号；按岗位词搜索，读取列表及所选职位完整详情。页面布局改变时重新观察，不能凭旧ref或索引盲点。
2. 将候选岗位、详情链接及描述存入工作目录；先审阅再生成投递批次。默认每批5–10个；确认稳定后可适量扩大。不同批次使用不同文件名。
3. 按职位ID去重，排除已确认投递、此前已投及提交结果未知的职位。相同公司下不同岗位可以分别评估；同一岗位不同追踪链接只算一个。
4. 选择卡片后再核对详情标题、公司及职位ID。通过可见的“立即投递”操作；如果还有选择简历/填写问答等表单，只按真实资料处理，未完成前不算提交成功。
5. 以明确成功提示或可归因到本次操作的投递记录为凭据。仅点击成功、退出码0、“继续沟通”或详情页“已投递”，均不足以证明本轮新增成功。尤其已有聊天的职位，投递成功弹窗可能不出现：记录为未知，单独核查，不能直接重试或充数。
6. 每批立即保存结果及确认时间，更新唯一成功数、英语岗位标记、未确认/失败原因与待投清单。截图按需保留。脚本超时或失联后，先收取同一进程/会话的结果并检查页面，避免整批重跑。

## 限额、验证与中断

- **每天额度已满、操作频繁、验证码、安全验证或登录失效时，立即结束提交批次。** 不再点击下一岗位，也不另启批次或切换账号绕过。可以保存已有结果，正常关闭提示后进行只读整理。需登录或验证时让用户在实际浏览器完成，不向聊天索取密码/验证码。
- 已观察到的提示是“今日投递已超过上限，明天再试吧！”；需同时识别“超过上限”和“达到上限”。不能因为只匹配后者而继续点下一个。具体额度及重置时间以平台当前状态为准，不能把一次投满的数量当作固定规则。
- 明日续投先重读当前页面与历史；旧限额弹窗不代表新一天仍被限额，也不能据此假定已恢复。正常关闭旧提示后，逐个执行并观察平台的新结果。
- 提交前失败且确定未点击投递的岗位可修复后重试；点击后结果不明，先核查记录，不自动重试。
- 保留目标和剩余数量，写清下一搜索词/候选文件/未完成批次、限额日期及恢复条件。用户要求定时继续时才调用应用的定时任务工具；不能用技能文件里的文字假装已安排。
- 使用用户现有浏览器，释放时只 `detach`，不要关闭浏览器或无关标签。

## 辅助脚本

需要重复收集、去重和记账时，使用 [scripts/jobs.py](scripts/jobs.py)。脚本只生成Playwright CLI函数、处理本地结果与报告，不直接登录、抓私有接口或自动筛选岗位。具体命令、数据格式及旧记录导入见 [references/helpers.md](references/helpers.md)。

UI模板来自2026年10月的一次智联操作，**每次使用前先通过当前快照验证DOM及提示文本**。生成脚本复制到任务工作目录再执行；需要适配时修改任务副本，不把候选人数据或特定聊天的进度写入技能目录。

交付应包含：本轮及累计的唯一确认成功数、目标剩余、英语/海外岗位情况、记录文件和未完成原因。只有原数量目标实际达到并核验后才宣布完成。
