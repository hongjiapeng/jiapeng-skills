# 智联招聘简历优化与回填

完成从真实经历梳理、改写到在线保存的流程。以用户指定方向为准；未指定时先利用现有资料改写，必要时询问目标岗位。仅讨论建议时不写入网站；用户已明确要求直接填写或保存时继续执行，不重复索取同一授权。

## 读取与改写

1. 定位用户指定的浏览器和 `https://i.zhaopin.com/resume`，核对简历所属人。不要将登录凭据、浏览器档案或候选人资料写入技能目录。
2. 先读完整经历，展开工作和项目栏的“查看全部”，等待条目实际加载。将修改前的相关文字、日期和求职意向备份到当前工作目录。导出备份时只保存简历所需信息，不导出Cookie、验证码或密码。
3. 根据目标岗位调整重点，保留真实的参与/负责范围。用业务场景、本人行动、已知交付结果组织内容；不得把“参与”升级为“主导”，也不虚构指标、技能、职级或填补经历空档。无事实支撑的提升百分比不写。
4. 将改写内容与网页操作分离。默认保留公司、时间、薪资、个人资料、求职状态和意向；只有用户要求且事实充分时才修改这些字段。已有任务授权不扩大为投递、沟通招聘方、购买服务或更改隐私权限。

## 连接与故障处理

- 优先使用用户指定且已登录的浏览器。遵循当前浏览器工具和适用 Computer Use / Playwright 技能的操作边界。
- 先做短探测：读取当前地址、找到编辑入口、打开一个编辑框。能列出标签页不代表能点击填写；读到正文也不代表已写入。
- 本机曾通过 Playwright CLI 的 `attach --extension=msedge` 跑通 Edge；这是可选的已验证恢复路径，不证明 CLI 对所有环境都优于其他方式。
- 同一连接方式连续两次控制失败时，先读工具的故障说明，停止同路径循环。若当前工具明确要求停止或用户已中止，则立即停止该回合；不得通过换工具绕过停止或安全限制。
- 用户允许且工具边界允许时，可切换 Playwright CLI。首次使用先读现有 Playwright 技能。不要为接管浏览器擅自复制用户档案、读取认证存储或调整安全配置。
- 页面跳回登录页时停止填写，保留草稿，让用户在实际受控浏览器中登录。用户不用向聊天提供密码或验证码。

终端接入、页面定位和 Windows 参数传递见 [references/site-workflow.md](references/site-workflow.md)。

## 回填

1. 每次先核对所属人及目标公司/项目，再打开编辑框。编辑按钮可能仅在悬停时显示；点击栏目标题后，等待对应可见按钮，不能对隐藏按钮反复点击。
2. 使用当前快照中的引用或已观察到的选择器。静态引用会随登录、刷新和表单切换失效。选择器失配时重新读取页面；不要根据旧的数字索引继续输入。
3. 一次处理一个条目。现有条目可使用下方辅助脚本；复杂或已变更的页面按最新快照操作。
4. 新增项目之前展开完整项目列表，核对同名条目、日期和描述。完全相同则跳过；同名但不同内容先核实，避免重试造成重复。先保存原有修改，再新增，不删除或覆盖其他项目。
5. 项目日期输入框曾为只读年月选择器；通过控件选择年月，选完等待弹层关闭，再处理下一个日期。具体方法见参考文档。
6. 通过 `inputValue()` 核对完整写入值再保存；保存后等待表单消失并检查展示内容。失败时先观察当前状态，不重新运行整批已保存操作。

### 现有条目的参数化辅助脚本

`scripts/build_update.py` 将工作目录中的 JSON 任务文件生成 CLI 可运行的函数文件。支持个人优势、工作描述和项目描述，**不修改日期或其他字段，不负责新增项目**。

每个任务指定候选人显示姓名、目标条目名称、期望原文和替换文案。脚本拒绝原文不匹配的覆盖；已是目标文案时跳过。工作/项目的开始和结束日期作为额外核对项，格式由实际编辑框读取，不能推算。

```powershell
python -X utf8 <skill-dir>/scripts/build_update.py <workspace>/resume-task.json --out <workspace>/output/playwright/resume-update.js
npx.cmd --yes --package @playwright/cli playwright-cli -s=zhaopin run-code --filename <workspace>/output/playwright/resume-update.js
```

任务格式、连接命令及失败恢复见参考文档。生成文件含候选人信息，应留在工作目录，不放入技能包。文件传递可避免 Windows `.cmd` 参数中的多行中文被截断；不得拼接未经转义的候选人文字到终端命令。

## 核验与交付

- 逐项记录已保存、未保存和跳过的条目。不要以点击成功或退出码为唯一完成依据。
- 完成所有保存后刷新一次页面；如存在未保存表单，先处理表单，不能用刷新丢弃内容。展开全部条目并等待目标条目实际出现，检查新文案、项目数量及日期。
- 日期可能在悬停时隐藏：可读取已观察到的条目日期节点文本，避免因视觉隐藏误判丢失。不得借此读取隐藏的应用状态或认证信息。
- 保存截图到工作目录的 `output/playwright/`，并在回复中嵌入一张能核对结果的截图。释放自动化连接时仅 detach，不关闭用户浏览器。
- 只报告已核实的保存结果、实际变更范围和仍需补充的事实。连接失败时准确说明“读取成功/填写成功/未保存”的阶段，不承诺未经证实的进度或时间。

## 维护范围

站点观察记录来自2026年10月的一次成功流程，布局、选择器和字数上限可能变化；每次仍需先检查当前页面。本技能未在其他招聘网站验证，不将本次连接故障解释成永久的平台限制。
